# Studio UX review · 0.2.8

Baseline: `5be1a147b22b7b751e19d523199b5042e3990f68` (0.2.7). Review date: 2026-09-17. This is a correction of the existing application, not a replacement of its architecture.

The previous release had the main UI elements but did not fully satisfy the promised behavior. Focused form values, edge drafts, graph-aware preview, exact failure navigation, actual recent usage and final-run summaries needed further work. The rows below distinguish implemented behavior from evidence. Passing automation is not proof of bug-free software or physical Windows acceptance.

## Reproduced failures, not just source inspection

On the baseline, the focused Ctrl+S browser scenario saved the old pipeline title. A timeout input showed the old inherited-label value after editing. VLM planning submitted its parent LLM cursor ID. A Validator-rejected graph retained its intermediate model as the trace Winner and had no final outcome. There was no structured accounting of the remaining queue. A separate test blocked screenshot preparation and received HTTP 200 from a settings write while the job was already active. These scenarios now run in the ordinary Go/UI suites.

Actual engine execution of a separate VLM followed by a catalog text stage already worked in 0.2.7; the mismatch was in preview/simulation. The repair preserves that working execution path and aligns the other two representations with it.

## Memory and privacy boundaries

The last-run prompt store is Go-owned, volatile and bounded to 16 snapshots of at most 32 KiB of string data each (about 512 KiB payload plus structure overhead). It stores only text template values and an image-attached boolean, never screenshot bytes. It is omitted from automatic job polling and trace/export, available through the explicit protected `/api/prompts/last` route, cleared on a new job or Clear, and gone on process exit. Provider secrets are redacted before storage. Truncated input is labelled as such rather than represented as the full original request.

Recent usage retains at most 30 unique catalog references and carries no prompts or credentials. It is written to the existing portable JSON on save/controlled exit, not to a second user file. User configuration is ignored by Git; safe distribution configuration contains no personal recents, keys or VPN secrets.

Simulation is bounded and hypothetical. It does not capture the screen, invoke providers, mutate live random/cursor state or prove cloud billing/retry behavior. Counts describe adapter calls; OpenCode internal SDK retries remain outside packet-level verification. All existing native capture, privacy, hotkeys, WebView2 lazy lifecycle and runtime isolation paths are retained.
