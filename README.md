# AIOverlay-go 0.2.8

Windows 10/11 x64: нативный AI-оверлей и встроенная Pipeline Studio на WebView2. Python, pip и Node для запуска не нужны. Обычный запуск не открывает браузер и не поднимает HTTP-интерфейс Studio.

## Запуск и обновление

Распакуйте `AIOverlay-go_Windows.zip` в новую папку и запустите `AIOverlay.exe`. Рядом должны оставаться `runtime` и `config.json`. Для переноса настроек сначала закройте обе версии, затем скопируйте прежний `config.json` рядом с новым EXE. Текущая схема конфигурации — 6. Конфигурации схем 1–5 автоматически мигрируются при загрузке. Списки моделей, transport, ключи и включение VPN сохраняются. Неизвестные поля сохраняются на всех уровнях, будущая неподдерживаемая schema отклоняется без изменения файла. Перед обновлением сохраните резервную копию config.json: после сохранения в схеме 6 старые сборки могут не прочитать файл.

При отсутствии WebView2 Runtime приложение показывает native-сообщение. Запустите `Install-WebView2.ps1` вручную: он скачивает официальный установщик Microsoft и проверяет Authenticode-подпись. Browser fallback отсутствует.

Повторная проверка нашла поведенческие пропуски в 0.2.7, несмотря на наличие основных элементов интерфейса. Сохранение и переключение пайплайна блокируются в core с начала захвата, а не только после запуска модели.

Из сводки открываются конкретные ключи и условие fallback. «Недавние» включает реально вызванные модели. Кнопка в предпросмотре prompt явно подставляет ограниченные текстовые данные последнего запуска; сама Studio не раскрывает их автоматически, снимок туда не сохраняется. Карта всех девяти UX-требований и границ проверки: `UX_REVIEW.md`. В релизе 0.2.8 использовалась схема 3; текущая ветка использует схему 6.

## Подключение провайдера через OpenCode

В Studio откройте **Подключения**, найдите провайдера и выберите **Via OpenCode** и нажмите «Подключить». Provider ID и переменные авторизации берутся из bundled Models.dev: вводить их вручную не нужно. Вставьте API-ключи, нажмите «Добавить», затем «Сохранить подключение». Поддерживаются строки с переносами и буквальным `\n`, повторы удаляются. После добавления видны только название ключа и последние четыре символа.

Кнопка «Модели» открывает каталог именно этого провайдера. Выбранная модель использует явно указанный транспорт `Via OpenCode`. Фильтр Direct предназначен для native-адаптеров; существующие Direct-подключения не заменяются OpenCode скрытно. Подключение можно сохранить отдельно, не применяя незаконченный черновик графа.

Ключи хранятся в открытом виде в переносимом `config.json`. Предупреждение находится рядом с вводом ключей и при экспорте. Не публикуйте этот файл и не прикладывайте его к отчёту об ошибке.

«Настроен» означает наличие конфигурации, а не проверенный баланс, регион или доступ ко всем моделям. API-key подключение не заменяет OAuth/device login, AWS/Azure identity и другие специальные способы авторизации. В этой версии такие login-процедуры не реализованы. OpenCode получает только ключ текущего провайдера; пользовательский CLI auth.json не импортируется.

## Модели и fallback без ручного списка

В инспекторе этапа выберите источник:

- **Мой список**: только добавленные вручную модели.
- **Каталог подключений**: модели настроенных подключений из каталога. Ручной список может быть пустым.
- **Сначала список, затем каталог**: выбранные модели образуют первую часть очереди, затем идут остальные подходящие модели.

Отбор учитывает подключение, включение провайдера, входную модальность, текстовый выход, фильтр FREE и порог качества. Для keyless OpenCode дополнительно используется bundled список разрешённых моделей. Наличие model ID в Models.dev само по себе не делает модель доступной.

По умолчанию у нового каталожного этапа включён фильтр FREE. FREE означает нулевую цену в метаданных, а не гарантию доступа без регистрации. Снятие фильтра допускает платные модели. У каталога нет объективной оценки качества: неоценённые модели имеют 0. Ручные оценки сохраняются. При ненулевом пороге такие модели пропускаются; кнопка «Разрешить модели без оценки» явно опускает порог до 0.

В каталожном режиме добавленные вручную модели задают индивидуальные приоритеты и оценки; отключённый слот исключает соответствующий маршрут. При равных приоритетах используются оценка качества, выбранный порядок подключений и стабильный provider/model ID. Полный список и причины отсева доступны через «Вся очередь / пропуски».

«Все модели» не означает неограниченные запросы. Например, список из 200 моделей при бюджете 8 вызовов не отправит 200 запросов. Новый ключ и повтор на том же ключе тоже расходуют лимит. Действуют ограничения этапа и всего пайплайна; интерфейс показывает меньшее из них.

## Последовательный, параллельный и отложенный запуск

Источник моделей и порядок запуска настраиваются отдельно. «Последовательно» пробует следующую модель после ошибки. «Одновременно» заполняет свободные места в пределах параллельного лимита. «С задержкой резерва» начинает с одной модели и добавляет следующую через заданный интервал, пока ответа нет; после ошибки свободное место может быть занято раньше.

Первый успешный непустой ответ допущенной модели завершает этап, конкурирующие попытки отменяются насколько позволяет транспорт. Стримы разных моделей не склеиваются. Отдельный Validator может проверить форму ответа, но это не доказательство его правильности.

Для TEXT ONLY можно выбрать отдельный этап зрения. Он виден над этапом решения, имеет собственные модели, fallback, prompts и лимиты. Его текст передаётся через `{{vision.text}}`; изображение в текстовую модель не отправляется.

## Studio как настройки оверлея

Клик по пайплайну слева сохраняет черновик и назначает выбранный пайплайн активным. Новый запрос оверлея использует его без отдельной кнопки «Запустить». Если сохранение не удалось или запрос ещё выполняется, активный пайплайн не меняется. Переключение уже сохранённых пайплайнов не сбрасывает прогретые провайдеры, round-robin и здоровье ключей.

Тяните пустое поле графа левой кнопкой. Средняя/правая кнопка или Space + перетаскивание двигают поле и поверх узлов. Ctrl + колесо меняет масштаб; «Уместить» показывает весь граф. Положение и масштаб сохраняются в `config.json`.

Обычные связи продолжают маршрут после ответа и не подписываются `success`. Клик по связи открывает условие перехода: после ответа, при любой ошибке или при конкретных ошибках. Для пояснения элемента удерживайте Alt и наведите указатель. Кнопка «Alt Подсказки» включает такой режим без удержания.

Внизу графа видны фактические попытки: модель, транспорт, провайдер, alias ключа и состояние. В «Запусках» доступны события START, FIRST TOKEN, старт резерва, победитель, исход, HTTP-статус, длительность и токены. OpenCode в текущем bridge возвращает готовый ответ: его TTFT/TPS показываются как «—», а не как выдуманные показатели стрима. Внешний runtime имеет собственную реализацию запросов; приложение не выдаёт свои события за сетевой аудит всех внутренних операций OpenCode.

### Память в обычной работе

Новый стандартный конфиг имеет `control_center.auto_open=false`: после запуска работают только core/overlay и нужные AI runtimes, а WebView2 Studio создаётся по запросу. Существующий пользовательский `config.json` сохраняет своё значение `auto_open`; настройка не переписывается миграцией. После закрытия Studio Windows может освобождать память дочерних WebView2-процессов не мгновенно, но приложение больше не удерживает скрытую Studio намеренно. Embedded OpenCode имеет отдельный lifecycle и этим изменением не выгружается.

## Захват и скрытая Studio

Ctrl+Shift+S анализирует экран активным пайплайном. Ctrl+Shift+X переключает Ghost Mode. Ctrl+Shift+C отменяет запрос, очищает и скрывает оверлей. Ctrl+Shift+O открывает Studio. Ctrl+Shift+Q завершает приложение (сохранённая конфигурация не трогается). Хоткеи переназначаются в «Приложении».

Studio теперь не остаётся скрытым WebView2-процессом. Кнопка «Закрыть Studio» и крестик сначала сохраняют валидный черновик, затем уничтожают текущую WebView2-сессию; overlay, hotkeys, scheduler и активный pipeline продолжают работать. Вернуть Studio можно хоткеем или кнопкой ⚙ на overlay — WebView2 будет создан заново и прочитает актуальный `config.json`. Иконки в области уведомлений больше нет: выход из приложения выполняется только явно хоткеем Ctrl+Shift+Q (переназначается). Studio — редактор config.json, её окно намеренно не применяется защита от захвата (`stealth` относится только к оверлею): аффинити окна на WebView2 у части драйверов обесцвечивает вывод.

«Приложение → Проверить захват» делает только предпросмотр, без AI-запроса. Только отдельная кнопка отправляет снимок в пайплайн. Если Studio открыта поверх рабочего экрана, на время захвата она скрывается, чтобы настройки не попали в снимок. Если Studio уже закрыта и выгружена, capture идёт напрямую без ожидания WebView2. Свёрнутое окно не восстанавливается.

Capture path: `GetDC → CreateCompatibleDC → CreateDIBSection → SelectObject → BitBlt → GdiFlush → скопированные BGRA → RGBA → JPEG в памяти`. GetDIBits не используется. Захват остаётся на одном OS thread до копирования пикселей и освобождения GDI; JPEG кодируется по Go-буферу, без screenshot-файла. При длинной стороне свыше 1800 px используется билинейное уменьшение.

Наш capture хранит снимок в RAM. Отдельный OpenCode runtime может сохранять сессионные данные на диске; после попытки bridge запрашивает удаление сессии, а после отмены также abort. Это не гарантия, что сторонний runtime вообще не пишет данные, и не гарантия хранения облачным сервисом.

## AI VPN только для запросов моделей

В общий `config.json` добавлена секция `vpn`. Если секции нет либо `vpn.enabled=false`, sing-box не запускается и сетевой путь остаётся обычным. Если `vpn.enabled=true`, AIOverlay лениво запускает bundled `runtime/sing-box/sing-box.exe` и направляет через него native provider adapters и сетевые запросы Embedded OpenCode. Ошибка запуска tunnel является fail-closed: приложение не переключается скрытно обратно на direct.

Studio → «Приложение» содержит runtime-настройки AI VPN. Раскройте «Изменить профиль»: поддерживается импорт VLESS/Hysteria2/Trojan ссылок в совместимых режимах, либо один sing-box outbound JSON, например VLESS, Hysteria2, TUIC, Trojan, Shadowsocks или VMess. Можно вставить и полный sing-box JSON, если в нём ровно один tunnel outbound: пользовательские `inbounds`, TUN, route и `set_system_proxy` намеренно игнорируются. DNS, необходимый выбранному outbound, сохраняется. Исходящее соединение с VPN endpoint использует IPv4; IPv6 literal в адресе сервера отклоняется. Многозвенные detour-профили требуют отдельного явного преобразования и не импортируются как будто они поддержаны. AIOverlay сам генерирует authenticated `mixed` inbound на `127.0.0.1` со случайным портом и случайными credentials. Windows system proxy не меняется, TUN-интерфейс не создаётся, LAN listener отсутствует. Поэтому tunnel не маршрутизирует трафик других приложений.

VPN-конфиг может содержать UUID, пароли и другие секреты. Он хранится в том же переносимом `config.json`; файл следует считать секретным. Кнопка «Проверить конфиг» выполняет структурную проверку, а на Windows также `sing-box check`. Рабочий sing-box запускается только при первом AI-запросе после включения; «Проверить конфиг» создаёт отдельный короткий процесс check, без AI-запроса.

Bundled runtimes закреплены по содержимому, а не по имени latest. OpenCode v1.18.31 берётся из официального `opencode-windows-x64.zip`; SHA-256 архива `0ecd7ffc7f26390ce7799e7bcd409e4f11c410144308a6a5b0fcdce63d871006`, а bundled `opencode.exe` — `0242a0dc705af67c90882b456a36b619883c1c786aad8fe071a1bc64e5d1d440`. Подробности находятся в `runtime/opencode/VERSION.txt`. sing-box 1.14.4 берётся из официального Windows amd64 release; SHA-256 исходного архива закреплён в `runtime/sing-box/VERSION.txt`. Лицензии находятся рядом с runtime-файлами. Если checkout содержит только Git LFS pointers, выполните `python3 scripts/materialize-runtimes.py`: helper скачивает только эти закреплённые официальные ZIP, проверяет SHA-256 архива и каждого извлечённого runtime-файла и лишь затем атомарно заменяет pointer. `python3 scripts/materialize-runtimes.py --check` выполняет только локальную проверку без сети.

## Privacy и процессы

Оверлей сохраняет существующую Windows capture-exclusion логику. Установленный display affinity не доказывает невидимость в каждом источнике OBS/WGC/DXGI. Физические проверки на Windows в этой среде разработки не выполнялись.

Основной EXE имеет собственные PE resources и AppUserModelID. WebView2 и OpenCode физически создают дочерние процессы; на вкладке Details они могут отображаться отдельно. Приложение не маскируется под стороннее ПО и не обещает один OS process.

## Сборка и build profile

Поля `build` в выбранном pre-build JSON являются входом сборки, а не runtime-настройкой. По умолчанию build scripts читают версионируемый безопасный `examples/config.example.json`, а не локальный runtime config. В Studio они больше не редактируются. Перед `scripts/build.ps1` или `scripts/build.sh` задайте `executable_name`, `product_name`, `file_description`, `company`, `version` и `icon_path` в build config. `cmd/buildmeta` до компиляции генерирует PE resources и `internal/buildinfo/generated.go`; поэтому уже собранный EXE не меняет имя, версию, иконку или AppUserModelID от последующего редактирования runtime JSON.

## Сборка и проверки

Для разработки нужны Go 1.27.3 или новее (минимум закреплён в `go.mod`), Git с Git LFS и Node.js 22 для UI-проверок. Race detector требует C-компилятор. Python 3 нужен только для `scripts/materialize-runtimes.py`. Windows x64 собирается через `scripts/build.ps1`, из Linux — через `scripts/build.sh`. Перед сборкой генерируются PE icon/version/manifest resources. Для обычного запуска приложения эти инструменты не нужны.

Единая проверка из корня репозитория:

```sh
scripts/check.sh
```

Она проверяет форматирование и согласованность Go-модулей, выполняет тесты, `go vet` для текущей платформы и Windows, собирает временный Windows EXE, проверяет JavaScript и публичный пример конфигурации. Для неё не нужны materialized LFS runtimes; `config.json`, `dist/` и `releases/` она не меняет.

Для DOM-тестов установите зависимости и запустите стандартную команду:

```sh
npm ci --prefix tests/ui
npm test --prefix tests/ui
```

Для полной проверки с race detector и Chromium:

```sh
(cd tests/ui && npx playwright install --with-deps chromium)
scripts/check.sh --race --ui
```

Доступен также `scripts/check.sh --dom`. UI runner собирает временный Go host, использует отдельную конфигурацию и не обращается к реальным моделям. GitHub Actions запускает полный набор проверок, `npm audit` и `govulncheck` для Linux/Windows; workflow находится в `.github/workflows/ci.yml`.

Аудит от 9 ноября 2026 года: [исправления, результаты и оставшиеся риски](docs/audits/2026-11-09.md). Проверка исходников AIOverlay не заменяет проверку внешних бинарников: в официальном sing-box 1.14.4 остаются известные замечания к его зависимостям, перечисленные в отчёте.

Production assets полностью встроены в EXE. `--headless` существует только для разработки; не открывайте его за пределами loopback.

Точные результаты и границы проверки: `VERIFICATION.md`. Состав архивов: `MANIFEST.sha256`, хэши ZIP: `releases/SHA256SUMS.txt` в рабочем дереве.


## Исправления аудита в 0.2.6

Подробная карта: `AUDIT_FIXES.md`. Исправлены 26 пунктов review baseline `261f569`: STA и синхронное закрытие WebView2, единая отмена capture/inference, независимые данные этапов, ключевой бюджет, проверка завершения child processes, hotkey rollback, строгая validation, сохранение диалоговых черновиков, изоляция bridge sessions, DNS/IPv4 политика, redaction и immutable trace. `GetDIBits` не возвращался, scheduler не заменялся цепочкой provider-specific условий.

Studio создаётся на отдельном STA thread с явными `CoInitializeEx`/`CoUninitialize`. Закрытие происходит на том же потоке: WebView2 controller Close, освобождение COM references, уничтожение HWND, завершение message loop, очистка профиля. Для этого используется небольшой локальный MIT fork прежней Go-обёртки (`third_party/go-webview2/PATCHES.md`), не fork браузера. Реальный размер освобождаемой памяти зависит от Windows/WebView2 и требует измерения на вашем ПК.

При закрытии Studio основной валидный черновик сохраняется. Новые правки, появившиеся во время сохранения, оставляют Studio открытой. Для незавершённого диалога провайдера доступны «Сохранить / Не сохранять / Отмена». Alt-подсказки остаются. Пока редактируется hotkey, старые actions временно не исполняются; lease восстанавливает регистрацию после потери редактора.

`Приложение → Диагностика` показывает отдельно requested и применённую Windows защиту, ошибки регистрации hotkeys и состояние VPN. Применённый display affinity не доказывает невидимость в любом OBS capture path. На старых Windows 10 до build 19041 используется ограниченный monitor-only режим, и это видно в диагностике.

Полный SaveConfig больше не сбрасывает прогретые engine/provider runtimes при изменении шрифта, раскладки, label или dispatch policy. Изменение настоящих параметров подключения пересоздаёт нужный набор сетевых адаптеров, но сохраняет engine и независимую статистику. Ghost hotkey меняет текущий сеанс; значение Ghost при следующем запуске задаётся отдельно в конфиге. Перемещение/resize overlay сохраняет геометрию.

### Prompts, выполнение и trace

`{{input.text}}` — исходный текст запроса, `{{previous.output}}` — результат предыдущего этапа, `{{vision.text}}` — извлечённый визуальный текст. Подстановка выполняется за один проход: template-подобный текст внутри входа не подставляется повторно. «Предпросмотр итогового prompt» использует тот же engine renderer без запроса модели.

Исходный screenshot остаётся в контексте run для fallback после Validator. Изображение не прикладывается к известной text-only модели после извлечения текста. Наличие текста/изображения для произвольной неизвестной каталогу модели требует корректной настройки пользователя.

Эффективные лимиты выводятся в событие `effective_limits`: slot override, затем pipeline, затем provider defaults, затем безопасные defaults. OpenCode получает лимит output tokens через поддерживаемую bundled-версией настройку `OPENCODE_EXPERIMENTAL_OUTPUT_TOKEN_MAX`; его runtime cache учитывает этот лимит. Буферизованный bridge по-прежнему не выдаёт выдуманные TTFT/TPS.

После отмены engine дожидается закрытия stream/error channels. Для некорректного стороннего адаптера ожидание cleanup ограничено 1500 мс и появляется `worker_cleanup_timeout`; успешное завершение cooperative transport проверяется regression-тестом. Это не доказательство мгновенной остановки inference на сервере провайдера. Защитный предел одного текстового ответа — 16 MiB.

### Synthetic benchmark

В разделе «Запуски» выберите 1–10 повторов (по умолчанию 3). Batch фиксирует pipeline/config на время сравнения, показывает выполненные и запрошенные повторы, winner, verdict, latency, медиану, success rate, доступные TTFT/TPS. Отмена относится ко всему batch. Правильность фиксированной fixture проверяется только для однозначного ответа Q4 / 210 или JSON `{"quarter":"Q4","profit":210}`. Неоднозначная свободная формулировка помечается «Проверить вручную», а не автоматически считается правильной по двум подстрокам. Pipeline автоматически не меняется.

### Git и сборка релизов

Рабочий `config.json` секретный и не отслеживается Git. Безопасный шаблон — `examples/config.example.json`. В source/release ZIP под именем `config.json` всегда кладётся выбранный проверенный шаблон. API keys, VPN profiles и private runtime statistics нельзя переносить в release template. Preflight отказывает при обнаружении этих данных и при LFS pointer вместо настоящего EXE/DLL.

После clone выполните `git lfs install --local`, `git lfs pull`, затем `git config --local core.hooksPath .githooks`. Локальные hooks сохраняют LFS pre-push/post-checkout integration; pre-commit проверяет staged JSON, а не только working copy. Hooks являются страховкой, не заменой review и не неизбежной защитой от намеренного `--no-verify`.

На Windows установите Go нужной версии и Node только для разработки/тестов. Для полной проверки Studio: `cd tests/ui`, `npm ci`, `npx playwright install chromium`, затем вернитесь в корень проекта. На Linux браузеру нужны системные библиотеки и fontconfig; они не входят в приложение.

Полная воспроизводимая сборка обоих ZIP:

```sh
go run ./cmd/release --race --ui --windows-verify
```

Команда выполняет safe-template/runtime preflight, генерацию PE resources, clean build, Go tests/vet/Windows vet, critical-repeat ×20, race (нужен C toolchain), JS syntax, DOM/Chromium, извлечение PE resources, manifests, ZIP CRC и clean extraction. Из распакованного Source ZIP заново запускаются tests/vet и Windows build с проверкой SHA-256 EXE. Перед релизом требуется clean Git tree; `--allow-dirty` предусмотрен только для локального кандидата. Пропущенные `--ui`, `--windows-verify` и `--race` проверки явно отмечаются в `RELEASE.json`.

Отдельная сборка EXE: `scripts/build.ps1` или `scripts/build.sh`. Оба скрипта по умолчанию используют безопасный шаблон. Параметры build profile укажите в нём **до** запуска сборки. Итоговые archives: `releases/AIOverlay-go_Source.zip`, `releases/AIOverlay-go_Windows.zip`; контрольные суммы — `releases/SHA256SUMS.txt`.

## Development HTTP mode

Только `--headless` создаёт HTTP listener, только на loopback IP. При запуске он выводит локальный URL с новым токеном в fragment. Для API нужен `Authorization: Bearer <token>`, Host/Origin проверяются, записи принимают `application/json`. Не публикуйте этот URL/токен. Native Studio использует отдельный in-process handler и не включает listener. В Windows headless mode overlay и global hotkeys не создаются.

## Границы VPN и внешних процессов

Приложение не меняет Windows proxy, routing table и TUN и не делает proxy общедоступным на LAN. OpenCode получает только приватный loopback proxy и ключ текущего провайдера. Это userspace routing, **не OS network sandbox**: настройка HTTP_PROXY не является доказательством запрета любого egress произвольного SDK. Packet capture реального Windows OpenCode/VPN требуется отдельно. При ошибке нашего VPN adapter запрос не переводится на Direct автоматически.

Child runtimes используют единственный Wait, наблюдаемое завершение и безопасную повторную инициализацию. На Windows дочерний процесс сначала suspended, затем включается в Job Object с kill-on-close и только после этого продолжается. Наличие процессов sing-box/OpenCode/WebView2 в Details Task Manager не скрывается. Изоляция child lifetime не гарантирует отсутствие дисковых записей OpenCode. Исходный screenshot нашего capture по-прежнему кодируется в RAM.
